# data/ranges — レンジデータ入力手順

## 大前提

**このディレクトリの数値は人間しか入力しない。** Claude は推測・生成・補完してはならない
（`CLAUDE.md` §2.1）。欠けているハンドを見つけても埋めない。バリデータが警告を出す。

わずかにズレたレンジを数千回反復するのは、何もしないより悪い。誤ったものを高速で自動化してしまう。

---

## 手順

1. 出典ツールでチャートを開く（フォーマット・レート・スタックを確認する）
2. `6max_100bb_rfi_<position>.json` を作る。ファイル名の `<position>` は小文字
3. `id` はファイル名（拡張子なし）と一致させる
4. `source` を**先に**埋める。空のままハンドを入力し始めない
5. `ranges` を入力する
6. `npm run validate` を通す

## ファイル形式

```json
{
  "schema_version": 1,
  "id": "6max_100bb_rfi_btn",
  "format": "6max",
  "stack_bb": 100,
  "spot": "RFI",
  "hero_position": "BTN",
  "villain_position": null,
  "actions": ["raise", "fold"],
  "source": {
    "name": "<ツール名 / フォーマット / レート>",
    "url": "<URL>",
    "retrieved_at": "2026-08-15",
    "entered_by": "juno",
    "notes": "<オープンサイズ、アンティ有無、ICM の有無など>"
  },
  "ranges": {
    "AA": { "raise": 1.0, "fold": 0.0 },
    "K9o": { "raise": 0.32, "fold": 0.68 }
  }
}
```

### 表記規則（`CLAUDE.md` §5）

- ランクは `A K Q J T 9 8 7 6 5 4 3 2`。`10` ではなく `T`
- 高いランクを先に：`AKs`。`KAs` はバリデータが**エラーにする**（自動で並べ替えない）
- ペアはサフィックスなし（`AA`）、スーテッドは `s`、オフスートは `o`
- 各ハンドの頻度合計は `1.0 ± 0.01`
- 記載の無いハンドは `fold: 1.0` として扱われる。全 169 を書く必要はないが、
  **意図的な省略か入力漏れかは区別できない**ので、`source.notes` に「フォールドは省略」と書く

### 入力を省略してよい場合

RFI のように「レイズしない = フォールド」が明らかなスポットでは、レイズ頻度が 0 より大きい
ハンドだけを書けばよい。バリデータは欠損件数を警告として出すが、ビルドは通る。

### ICM の扱い（v0.4 で重要）

プッシュ/フォールド表を入れるときは、**ICM 補正入りかチップ EV ベースかを `source.notes` に必ず書く。**
両者を混ぜて反復すると学習が壊れる（`plan.md` v0.4）。

## テスト用フィクスチャについて

`tests/fixtures/` に置いてあるチャートは**合成値で、実戦の学習には使えない**。
バリデータと採点ロジックの検証専用。`data/ranges/` にコピーしないこと。
